# 新手教程（合订本）

> 给三位零基础同事。
> 目标：从“拿到仓库地址”到“每天能独立改一页、提交、上线”。
> 第一次配置 2–3 小时；之后每页 30–90 分钟。

## 一页纸：你要做什么

我们在做一个网页解谜 demo：玩家打开一个虚构的社交平台，从帖子、评论、新闻里找线索，最后指认嫌疑人，触发不同结局。

你是四个人之一，负责几条页面。代码由 AI 写；你负责说清楚要什么、看效果、改文字和样式、测试、提交。

每天只有三个动作：

- **Pull**：把别人上传的改动拉到本地。
- **Commit**：给这次修改拍一张快照，写一句说明。
- **Push**：把快照上传到云端。

一张图：

```
Pull → 领页 → 改 → 预览 → 微调 → 自检 → Commit → Push → 线上验收
```

## 第一天清单（30 分钟）

目标：改一行字，推到线上。

- [ ] 接受 GitHub 邀请
- [ ] 安装 GitHub Desktop，克隆仓库
- [ ] 安装 VS Code，打开项目文件夹
- [ ] 安装 Live Server，打开 `index.html`
- [ ] 改 `weibo/index.html` 里一句话
- [ ] Commit + Push
- [ ] 打开线上地址，确认改动生效

做完这一遍，再回头看第 1、3 章。

## 阅读路线

- **第一次**：一页纸 → 第一天清单 → 第 1 章 → 第 3 章 → 附录 B。
- **第二次**：第 2 章（装 DSH 和可视化编辑器）。
- **负责人**：附录 D。
- **卡住**：先查附录 B，再找负责人。

# 1. 加入项目

## 1.1 你会拿到什么

- 仓库地址：`https://github.com/JasonJ578/find-your-name`
- 一封 GitHub 邀请邮件
- 本手册
- 在线领页表的链接（负责人发）
- 你负责哪几页（负责人告诉你）

## 1.2 注册 GitHub，接受邀请

1. 打开 https://github.com ，点 `Sign up`。
2. 填邮箱、密码、用户名。用户名会出现在网址里，想好再定。
3. 去邮箱点验证链接。
4. 把用户名发给负责人，让他邀请你。
5. 收到邮件后点 `Accept invitation`。

没有接受邀请也能看代码，但不能上传。

## 1.3 安装 GitHub Desktop，克隆仓库

1. 打开 https://desktop.github.com ，下载 Windows 版。
2. 安装，打开，选 `Sign in to GitHub.com`，用刚注册的账号登录。
3. 填名字和邮箱（会写进每次提交记录）。
4. `File` → `Clone repository`。
5. 选 `URL` 标签，粘贴：

```
https://github.com/JasonJ578/find-your-name.git
```

6. 本地路径选一个**不含中文和空格**的目录，例如：

```
D:\work\find-your-name
```

7. 点 `Clone`。

## 1.4 目录长什么样

```
find-your-name/
├── index.html              封面
├── weibo/                  微界线
├── assets/css/             公共样式
├── templates/              新页面模板
├── tools/                  脚本和本地编辑器
├── docs/                   项目文档
├── 新手教程/               这份手册，不进 Git
├── preview.cmd             双击预览
└── editor.cmd              拖 HTML 进去编辑
```

你主要改 `weibo/`、以后的 `news/`、`chat/`。

## 1.5 第一次打开预览

1. 打开 VS Code，`File` → `Open Folder`，选 `D:\work\find-your-name`。
2. 左侧扩展图标，搜索 `Live Server`，作者 Ritwick Dey，点 `Install`。
3. 在文件树里右键 `index.html` → `Open with Live Server`。
4. 浏览器会打开 `http://127.0.0.1:5500/`。

改完文件按 `Ctrl+S`，浏览器会自动刷新。

## 1.6 第一次改动：改一行、提交、上线

1. 打开 `weibo/index.html`，找到“昨晚 23:40 我还在公司”，改一个词。
2. 保存，浏览器里看效果。
3. 打开 GitHub Desktop，左下角写：

```
[微界] 首页：第一次改动测试
```

4. 点 `Commit to main`，再点 `Push origin`。
5. 等 1 分钟，打开：

```
https://JasonJ578.github.io/find-your-name/weibo/
```

看到改动就成功了。

如果推送被拒绝，先 `Pull origin` 再推。如果报连接被重置，先换网络（手机热点），还不行找负责人。

# 2. 装工具

## 2.1 你需要哪些软件

| 软件 | 用途 | 必须 |
|---|---|---|
| GitHub Desktop | 克隆、提交、推送 | 必须 |
| VS Code + Live Server | 改文字、本地预览 | 必须 |
| Python 3.9+ | 预览脚本、可视化编辑器 | 必须 |
| DeepSeek Harness（DSH） | 让 AI 生成和修改页面 | 必须 |
| 项目自带 `preview.cmd` / `editor.cmd` | 一键预览、可视化编辑 | 必须 |
| HTML Workbench 插件 | 在 DSH 右侧栏里编辑 | 可选 |

## 2.2 VS Code + Live Server

第 1.5 节已经装过。再确认两件事：

- 能 `Open Folder` 打开整个项目，而不是只打开一个文件。
- 右下角编码显示 `UTF-8`。

## 2.3 Python

1. 打开 https://www.python.org/downloads/ ，下载 Windows 安装包。
2. 安装时**务必勾选** `Add python.exe to PATH`。
3. 装完新开一个 PowerShell，输入：

```powershell
python --version
```

能看到 3.9 以上就行。

如果输入 `python` 弹出微软商店，说明没装好或没勾 PATH，重新装一次。

## 2.4 DeepSeek Harness（DSH）

DSH 是负责人电脑上那套 DeepSeek Harness。安装包找负责人拿，不要从不明来源下载。

1. 安装后打开，按提示登录、配置模型。
2. 如果卡在登录或模型配置，找负责人。
3. 用它做三件事：
   - 读 `docs/项目约定.md`，按约定生成页面。
   - 改一个指定文件、一个指定交互。
   - 解释控制台报错。

不要让它“顺便把整个项目重写一遍”。一次只做一页、一件事。

如果命令行里提示 `dsh` 不是命令，用完整路径调用，或让负责人帮你把安装目录加进 PATH。

## 2.5 可视化编辑器

有两种用法，任选一种。**推荐方案 A**，最稳。

### 方案 A：项目自带的 editor.cmd（推荐）

1. 在项目文件夹里找到 `editor.cmd`。
2. 把要改的 HTML 文件**拖到 `editor.cmd` 上**，松手。
3. 第一次会下载编辑器组件，等 1–2 分钟。
4. 浏览器打开 `http://127.0.0.1:4317/`。
5. 点选元素，改文字、颜色、位置，点保存。
6. 回到预览页刷新。

### 方案 B：DSH 右侧栏插件（可选）

1. 找到 DSH 安装目录，例如 `E:\DS Harness`。
2. 打开 PowerShell，执行（把路径换成你自己的）：

```powershell
& "<DSH 安装目录>\resources\runtime\cli\bin\dsh.cmd" plugin --profile desktop add @vibe-x/dsh-html-workbench
```

3. 完全退出 DSH，重新打开，浏览器里按 `Ctrl+Shift+R`。
4. 右上角出现按钮，点开，选 `weibo/index.html`。

如果右上角没有按钮：把窗口最大化、硬刷新、完全重启；还不行就用方案 A。

### 两条共同规则

- **不要手改页面里的 `<style>` 块**，它由 `assets/css` 生成。
- 改全站颜色、字号、间距：改 `assets/css/`，然后运行：

```powershell
python tools/inline-css.py --force
```

## 2.6 装完自检

- [ ] GitHub Desktop 能 `Pull`，没有报错
- [ ] Live Server 能打开 `http://127.0.0.1:5500/`
- [ ] `python --version` 有输出
- [ ] 拖 HTML 到 `editor.cmd`，能打开 `127.0.0.1:4317`

# 3. 每天的开发流程

## 3.1 开工：Pull

1. 打开 GitHub Desktop。
2. 点 `Fetch origin`。
3. 有更新就点 `Pull origin`。

不要在自己没 Pull 的情况下直接改一整天。

## 3.2 领页

1. 打开负责人发的在线领页表。
2. 找一行“待做”。
3. 负责人一栏写自己的名字，状态改“进行中”。
4. 群里说一声“我领了 P05”。
5. 一页做完再领下一页，不要同时开三页。

## 3.3 用 AI 生成或修改

1. 打开 DSH，新对话。
2. 先贴 `docs/项目约定.md`，或直接说“先读 `docs/项目约定.md`”。
3. 再贴需求单：

```
【页面】weibo/post-02.html
【作用】玩家在这里找到什么线索
【参照】weibo/index.html 的页头、导航、卡片
【内容】
- 主贴：……
- 评论 5 条：……
【交互】
- 点击某元素 → 跳到哪个页面
【不要做】
- 不要引入外部库，不要写行内颜色
```

4. 一次只让它做一页。
5. 输出保存到对应路径，例如 `weibo/post-02.html`。
6. 如果新页面带 `<link>` 外链样式，运行：

```powershell
python tools/inline-css.py
```

## 3.4 本地预览

1. 双击 `preview.cmd`。
2. 浏览器打开 `http://127.0.0.1:8000/`。
3. 用 `127.0.0.1`，不要用 `localhost`。
4. 把自己改的页面和相邻页面都点一遍。

## 3.5 可视化微调

1. 把 HTML 拖到 `editor.cmd`。
2. 点选元素，改文字、颜色、间距、位置。
3. 保存。
4. 回预览页刷新。

只改这一页的局部样式可以；全站样式走 `assets/css` 和 `inline-css.py --force`。

## 3.6 自检

- [ ] 窗口拉到手机宽度，没有横向滚动条
- [ ] 所有链接都点一遍，没有 404
- [ ] 浏览器控制台没有红色报错
- [ ] 图片不模糊、不超过 300KB
- [ ] 交互元素有固定的 `data-*` 名字
- [ ] 刷新后进度还在

## 3.7 提交：Commit + Push

1. GitHub Desktop 左下角写说明，例如：

```
[微界] 帖子详情：加时间线矛盾线索
```

2. 点 `Commit to main`。
3. 点 `Push origin`。

提交信息格式：`[哪条线] 哪一页：做了什么`。

## 3.8 线上验收 + 写变更

1. 等 1 分钟，打开：

```
https://JasonJ578.github.io/find-your-name/
```

2. 把刚改的页面再点一遍，按 `Ctrl+Shift+R` 强制刷新。
3. 在 `docs/变更记录.md` 末尾追加一条，写清日期、名字、改了什么。
4. 不会改 Markdown 的话，把内容发给负责人，让他代记。

## 3.9 一张图

```
Pull → 领页 → AI 生成/修改 → 预览 → 微调 → 自检 → Commit → Push → 线上验收 → 写变更
```

# 4. 规则与注意事项

## 4.1 四条禁令

1. 不改别人的页面，除非对方同意。
2. 不动 `assets/css/`、`tools/`、`docs/项目约定.md`，这些是公共的。
3. 不提交大图（单张超过 1MB 先压缩），不提交 `node_modules`、`*.psd`。
4. 不删除 `.git` 文件夹，不重命名别人的文件。

## 4.2 命名与目录

- 文件夹、文件名用英文小写 + 连字符：`post-02.html`。
- 图片放 `assets/img/<线>/`，先转 WebP。
- 交互元素用 `data-*` 起固定名字，名字定下后不要改。
- 线索 ID 用 `c01`、`c02`；旗标用 `seen_post_01`。

## 4.3 不要提交什么

Git 只同步**已提交、且没被忽略**的文件。下面这些永远不要进 Git：

- `新手教程/`（Word 版，负责人本地分发）
- `docs/交接-本地.md`
- `.html-workbench/`、`__pycache__/`、`.dsh-office-*/`
- `node_modules/`、`*.psd`、`*.ai`
- 超过 10MB 的单个文件

提交前先看一眼 `git status`，确认没有意外文件。

## 4.4 冲突处理

现象：Pull 时提示 conflict，文件里出现 `<<<<<<<`。

原因：两个人改了同一页的同一段。

处理：

1. 不要硬点合并。
2. 找负责人，一起看保留谁的版本。
3. 另一个人把改动重新加一遍。
4. 提交前再跑一次页面。

预防：一页同一时间只归一个人；要改别人的页，先在群里说。

## 4.5 交接与求助

1. 先查附录 B 的故障表。
2. 再看 `docs/单页制作流程.md`。
3. 还不行，把**截图 + 你做了什么 + 报错原文**发给负责人。

不要只说“坏了”。说清楚“我点了哪里、出现了什么”。

# 附录 B 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| `python` 不是命令 | 没装或没勾 PATH | 重装 Python，勾 Add to PATH |
| `git` 不是命令 | 没装 Git | 装 GitHub Desktop，它自带 Git |
| 网页拒绝连接 | 预览服务没开 | 双击 `preview.cmd`，用 `127.0.0.1` |
| 页面没样式 | 没同步样式 | `python tools/inline-css.py` |
| 编辑器打不开 | 没拖文件 / 服务没起 | 重新拖 HTML 到 `editor.cmd` |
| DSH 右上角没按钮 | 插件没装进 desktop profile | 用方案 A 的 `editor.cmd` |
| 打开地址提示 401 | 手动开了 DSH 的裸地址 | 用 DSH 自己打开的窗口 |
| 推送被拒绝 | 远程有新提交 | 先 Pull，再 Push |
| 冲突 | 两人改同一页 | 停手，找负责人 |
| 中文乱码 | 文件不是 UTF-8 | VS Code 右下角改 UTF-8 保存 |
| 推送报连接被重置 | GitHub 网络被重置 | 换网络（手机热点），还不行找负责人 |
| 端口 8000 被占用 | 之前的服务没关 | 关掉旧窗口，或重启电脑 |
| Word 文件写不进去 | 文件正被 Word 打开 | 关掉 Word 再导出 |

# 附录 D 负责人专用

这一节是给负责人看的，新人可以跳过。

## D.1 建仓库

1. GitHub 右上角 `+` → `New repository`。
2. 名字 `find-your-name`，选 Public。
3. 三个勾都不要勾（README、.gitignore、license）。
4. 建完把 HTTPS 地址发给本地仓库。

## D.2 开 Pages

1. 仓库 `Settings` → `Pages`。
2. Source 选 `Deploy from a branch`。
3. Branch 选 `main`，目录 `/ (root)`，保存。
4. 等 1–2 分钟，地址是 `https://JasonJ578.github.io/find-your-name/`。

## D.3 邀请同事

`Settings` → `Collaborators` → `Add people`，输入用户名，权限 `Write`。

## D.4 推送通道

如果 `github.com` 的 HTTPS 被网络重置：

- 本机已配置部署密钥 + `ssh.github.com:443`，remote 用 SSH。
- 不要把 remote 随意改回 HTTPS。
- 不要把部署密钥的私钥发给别人。

## D.5 页面清单

- 日常用在线共享表格领页。
- 里程碑时把在线表同步回 `docs/页面清单.md`，提交一次。
- 其他人不用改这个文件。

## D.6 交接与变更

- 每次收工更新 `docs/交接-本地.md`（只在本地，不提交）。
- 在 `docs/变更记录.md` 末尾追加一条。
- 每周备份一次 `docs/交接-本地.md` 和 `新手教程/`。
