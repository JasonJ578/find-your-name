# Git 同步策略

> 四个人共用 `main`。这份文档说明：每次 pull / push 到底会带哪些文件，以及哪些东西永远不该进 Git。

## 一句话

Git 只同步**已经提交、且没有被 `.gitignore` 排除**的文件。

## 三种状态

| 状态 | 例子 | pull 会更新 | push 会带上 |
|---|---|---|---|
| 已跟踪 | HTML、CSS、`docs/` 下的 Markdown、脚本、模板 | 会 | 会（只带已提交的） |
| 未跟踪、未忽略 | 新图片、新页面，还没 `git add` | 不会 | 不会 |
| 已忽略 | 本地交接、`新手教程/`、运行缓存 | 不会 | 不会 |

## 当前仓库同步什么

- 页面：`index.html`、`weibo/`
- 样式：`assets/css/`
- 模板与脚本：`templates/`、`preview.cmd`、`editor.cmd`、`tools/`
- 文档：`docs/` 下的 Markdown
- 规则：`AGENTS.md`、`.gitignore`

**不同步：**

- `新手教程/`（Word 版，负责人本地分发）
- `docs/交接-本地.md`
- `.html-workbench/`、`__pycache__/`、`.dsh-office-*/`
- `node_modules/`、`*.psd`、`*.ai`、`.vscode/`
- 本机安装的软件、浏览器里的游戏进度、运行中的服务

## pull 做什么

- 拉取远程 `main` 的新提交，更新已跟踪文件。
- 不删除未跟踪文件。
- 不碰已忽略文件。
- 本地未提交改动与远程冲突时，会拒绝，先处理再 pull。

## push 做什么

- 只上传已经 commit 的内容。
- 没 commit 的改动不会上传。
- 远程有新提交时会被拒绝，先 pull。

> Commit 是拍照，Push 是上传照片。

## 四条铁律

1. 只用一个 `main`，不开长期分支。
2. 动手前 Pull，收工前 Commit + Push。
3. 一页同一时间只归一个人。
4. 冲突不硬合，找负责人。

## 大文件与二进制

- 图片先压缩，单张不超过 300KB。
- 单文件超过 10MB 不进 Git；超过 50MB 考虑 LFS 或外链。
- Word、PSD、视频是二进制，每次改动都是新版本；只在版本节点提交。
- `新手教程/` 不进 Git，避免仓库被 docx 撑大。

## 提交前检查

- [ ] `git status` 里没有意外文件
- [ ] 没有大图、临时文件、缓存
- [ ] 提交信息写清“哪条线、哪一页、做了什么”
- [ ] 先 Pull 再 Push

## 冲突处理

1. 停手，不要硬点合并。
2. 找负责人，一起看保留谁的版本。
3. 另一个人把改动重新加一遍。
4. 提交前再跑一次页面。

## 备份

- GitHub 是代码的备份。
- `docs/交接-本地.md` 和 `新手教程/` 不在 Git，建议每周复制到网盘或 U 盘。
