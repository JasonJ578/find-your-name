# 新手配置教程

> 给完全没有技术背景的同事。
> 全部用图形界面，不需要懂代码；需要敲命令的地方会写清楚“复制哪一行”。
> 预计第一次配置 60–90 分钟。

---

## 0. 你最终要会做什么

```
每天早上：Pull（拉最新）
白天：改自己负责的网页 → 本地看效果 → 用可视化工具调
收工前：Commit（记录）→ Push（上传）
```

你不需要理解 Git 的原理，只要记住这三个动作。

---

## 1. 三个词

- **仓库**：项目在云端的共享文件夹。
- **Commit（提交）**：给这次修改拍一张快照，写一句说明。
- **Push（推送）**：把快照上传到云端，别人才能看到。

Pull 就是“把别人上传的改动拉到本地”。

## 2. 第一天：把项目拿到电脑上

### 2.1 注册 GitHub

1. 打开 https://github.com ，点 `Sign up`。
2. 填邮箱、密码、用户名。**用户名会出现在网址里**，想好再定。
3. 去邮箱点验证链接。

### 2.2 接受邀请

找项目负责人，把你的 GitHub 用户名给他，让他邀请你。

你会收到一封邮件，点里面的 `Accept invitation`。没有邀请就只能看，不能上传。

### 2.3 安装 GitHub Desktop

1. 打开 https://desktop.github.com ，下载 Windows 版。
2. 安装，打开，选 `Sign in to GitHub.com`，用刚注册的账号登录。
3. 填名字和邮箱（会写进每次提交记录）。

### 2.4 把项目克隆到本地

1. GitHub Desktop → `File` → `Clone repository`。
2. 选 `URL` 标签，粘贴：

```
https://github.com/JasonJ578/find-your-name.git
```

3. 本地路径选一个**不含中文和空格**的目录，例如：

```
D:\work\find-your-name
```

4. 点 `Clone`。

### 2.5 检查

打开那个文件夹，应该能看到 `index.html`、`weibo`、`assets`、`docs` 这些。

---

## 3. 第二天：改文字并预览

### 3.1 安装 VS Code

1. 打开 https://code.visualstudio.com ，下载并安装。
2. 打开后，`File` → `Open Folder`，选 `D:\work\find-your-name`。

### 3.2 安装 Live Server

1. 左侧点扩展图标（四个方块）。
2. 搜索 `Live Server`，作者是 Ritwick Dey，点 `Install`。

### 3.3 预览

1. 左侧文件树里找到 `index.html`。
2. 右键 → `Open with Live Server`。
3. 浏览器会打开 `http://127.0.0.1:5500/`。

以后改完文件，保存（`Ctrl+S`），浏览器会自动刷新。

### 3.4 找到你的页面

负责人会告诉你负责哪几页。比如你负责 `weibo/post-02.html`，就在左侧找到它，直接改文字。

> 只改文字和图片，不要动 `<style>` 那一大段，也不要动 `data-` 开头的名字。

## 4. 第三天：用可视化编辑器

### 4.1 安装 Python

1. 打开 https://www.python.org/downloads/ ，下载 Windows 安装包。
2. 安装时**务必勾选** `Add python.exe to PATH`。
3. 装完新开一个 PowerShell，输入：

```powershell
python --version
```

能看到版本号（3.9 以上）就行。

### 4.2 打开编辑器

1. 在项目文件夹里找到 `editor.cmd`。
2. 把你要改的 HTML 文件**拖到 `editor.cmd` 上**，松手。
3. 第一次会下载编辑器组件，等一两分钟。
4. 浏览器打开 `127.0.0.1:4317`，左边是画布，右边是属性面板。

### 4.3 改

- 点一下元素，选中。
- 右侧改文字、颜色、字号、间距。
- 选中后可以直接拖动位置、拉大小。
- 改完点保存。

### 4.4 看效果

回到预览页刷新。如果没有样式，运行：

```powershell
python tools/inline-css.py
```

## 5. 第四天：用 AI 加逻辑

逻辑指的是“点了会怎样、密码对不对、结局怎么判”。这部分让 AI 写，你负责说清楚要什么、然后测试。

### 5.1 打开 AI

用 DSH，或者任何你顺手的 AI 对话工具。

### 5.2 先贴项目约定

把 `docs/项目约定.md` 的内容贴进去，或者直接说：

> 先读 `docs/项目约定.md`，再改 `weibo/post-02.html`。

### 5.3 描述你要的交互

模板：

```
【页面】weibo/post-02.html
【要做的交互】
- 点击“23:04”这个时间，记录一条线索 c01
- 记录后按钮变灰，并弹一个提示
【不要做】
- 不要改页面结构和样式
- 不要改其他文件
```

### 5.4 一次只改一件事

不要说“顺便把另外两页也改了”。一次一个交互，改完测试，再下一个。

### 5.5 测试

- 打开页面，点一下，看有没有反应。
- 按 `F12` 打开控制台，看有没有红色报错。
- 刷新页面，看记录还在不在。

### 5.6 出问题怎么办

把**控制台的红色报错**和**你做的操作**一起发给 AI，不要说“坏了”，要说“我点了哪里、出现了什么”。

## 6. 每天的标准动作

**开工前：**

1. 打开 GitHub Desktop。
2. 点 `Fetch origin`，有更新就点 `Pull origin`。

**改的时候：**

- 只改自己负责的页面。
- 改完保存，浏览器里看一眼。

**收工前：**

1. GitHub Desktop 左下角写一句说明，例如：

```
[微界] 帖子详情：补充第 3 条评论
```

2. 点 `Commit to main`。
3. 点 `Push origin`。

**一天至少同步一次，不要攒一周。**

---

## 7. 冲突了怎么办

现象：Pull 的时候提示 conflict，文件里出现 `<<<<<<<`。

原因：两个人改了同一页的同一段。

处理：

1. **不要硬点合并。**
2. 找项目负责人，一起看保留谁的版本。
3. 另一个人把改动重新加一遍。

预防：一页同一时间只归一个人；要改别人的页，先在群里说。

---

## 8. 四条禁令

1. 不改别人的页面，除非对方同意。
2. 不动 `assets/css/`、`tools/`、`docs/项目约定.md`，这些是公共的。
3. 不提交大图（单张超过 1MB 先压缩），不提交 `node_modules`、`*.psd`。
4. 不删除 `.git` 文件夹，不重命名别人的文件。

---

## 9. 遇到问题找谁

1. 先看本文附录 B 的故障表。
2. 再看 `docs/单页制作流程.md` 的故障表。
3. 还不行，把**截图 + 你做了什么 + 报错原文**发给负责人。


## 附录 B 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| `python` 不是命令 | 没装或没勾 PATH | 重装 Python，勾 Add to PATH |
| `git` 不是命令 | 没装 Git | 装 GitHub Desktop 即可，它自带 Git |
| 网页拒绝连接 | 预览服务没开 | 双击 `preview.cmd`，地址用 `127.0.0.1` |
| 页面没样式 | 没同步样式 | `python tools/inline-css.py` |
| 编辑器打不开 | 没拖文件 / 服务没起 | 重新拖 HTML 到 `editor.cmd` |
| 推送被拒绝 | 远程有新提交 | 先 Pull，再 Push |
| 冲突 | 两人改同一页 | 停手，找负责人 |
| 中文乱码 | 文件不是 UTF-8 | VS Code 右下角改 UTF-8 保存 |

## Mac 用户

上面大部分步骤一样：GitHub Desktop、VS Code、Python 都有 Mac 版。

区别只有一个：`editor.cmd` 是 Windows 脚本。Mac 上打开“终端”，进入项目目录，运行：

```bash
python3 tools/workbench/scripts/workbench.py open "weibo/index.html" --editor-root . --port 4317
```

其余照旧。
