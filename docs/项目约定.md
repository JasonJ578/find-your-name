# 项目约定

> 每次让 AI 写页面前，先把这一整段贴在对话开头。
> 它比任何形容词都管用，能避免八成的返工。

---

## 项目是什么

《Find Your Name》是一个网页解谜 demo。玩家在虚构的社交平台上看帖子、点链接、找线索，最后在指认页把线索拖到板上，系统判断线索够不够，给出不同结局。

纯静态网站：没有服务器、没有数据库、没有构建步骤，部署在 GitHub Pages。

## 技术底线

- 只用原生 HTML + CSS + JavaScript。
- 不引入任何框架、构建工具、CDN、外部字体、图标库。
- 每个页面一个独立的 HTML 文件，双击能打开。
- 所有资源用相对路径。
- 文件编码统一 UTF-8。

## 页面模式

每页开头必须写一行注释，标明模式：

```html
<!-- PAGE-MODE: flow -->
```

或

```html
<!-- PAGE-MODE: canvas -->
```

- **flow**：信息流、文章、聊天、登录页。正常文档流，宽度自适应，内容多了自然滚动。
- **canvas**：封面、案发现场、结局插画。固定 16:9，元素绝对定位，整块缩放。
- 一页只能有一种主模式，不要混。

## 样式

- 颜色、字号、间距、圆角只用 `assets/css/theme.css` 里的 CSS 变量，例如 `var(--color-bg)`、`var(--space-4)`。
- 不在 HTML 里写 `style="..."`，不写死颜色值。
- 类名用小写 + 连字符：`.post-card`、`.comment-item`、`.profile-header`。
- 页面结构用语义标签：`header`、`nav`、`main`、`article`、`section`、`footer`。

## 交互

- 需要脚本读取的元素，用 `data-*` 标记，例如 `data-clue="c01"`、`data-action="open-profile"`。
- **这些名字一旦定下，任何人不得修改。** 脚本靠它找元素。
- 每页的脚本写在文件末尾的 `<script>` 里，用立即执行函数包起来，避免全局变量冲突。
- 进度只通过 `assets/js/state.js` 读写，不直接操作 localStorage。
- 线索 ID 用 `c01`、`c02`；旗标用 `seen_post_01`、`has_key` 这种动宾结构。

## 响应式

- 必须有 `<meta name="viewport" content="width=device-width, initial-scale=1">`。
- 主内容容器：`max-width: 1100px; margin: 0 auto; padding: 0 16px;`。
- 信息流列：`max-width: 600px;`。
- 图片：`max-width: 100%; height: auto;`。
- 文字容器不要写死高度。
- 至少检查 375px 和 1440px 两个宽度，不能出现横向滚动条。

## 素材

- 图片用 WebP，宽度不超过 1600，单张不超过 300KB。
- 头像 200×200 足够。
- 公共图放 `assets/img/common/`，页面专属图放 `assets/img/<页面名>/`。
- 先建占位文件，再让 AI 引用；不要让它编造不存在的文件名。

## 不要做

- 不要重写页头、导航、页脚的结构。
- 不要改 `data-*` 名字。
- 不要改 `theme.css`、`state.js`、`game.js`，除非任务明确要求。
- 不要引入任何第三方库。
- 不要用 `position: fixed` 做整页布局。
- 不要把信息流页做成绝对定位的画布。

## 输出要求

- 输出**完整** HTML 文件，不要省略号，不要“其余同上”。
- 生成后自检三件事：窄窗口不横向滚动、控制台无报错、链接指向存在的文件。
- 如果任务需要新素材，先用占位色块或占位文件名，并在结尾列出需要补的素材清单。
